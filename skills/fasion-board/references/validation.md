# 分镜输出校验

## 输入校验

1. 当前任务目录存在 `role.json`，且文件可解析。
2. 输入包含顶层 `role`，或包含非空 `roles` 数组。
3. 角色至少提供身份、外观、造型和一致性信息；缺失项不得被臆造为固定角色特征。

## 输出校验

1. `output/board.json` 是合法 JSON，使用双引号，无注释、尾随逗号或 YAML 语法。
2. 顶层 `skill` 为 `fasion-board`，`version`、`language`、`source_role`、`character_lock`、`shots` 和 `inferred_items` 均存在。
3. `shots` 数量恰好为 5，且景别按远景、全景、中景、近景、特写顺序出现。
4. `shot_id` 唯一，`prompt`、`prompt_zh` 和 `negative_prompt` 均非空。
5. 五条 Prompt 均保留角色姓名、年龄阶段、核心外观、服装和固定识别锚点。
6. 景别差异真实可见，不能仅修改镜头名称而保持相同构图和视觉职责。
7. 远景展示环境关系，全景展示完整造型，中景展示动作互动，近景展示面部，特写展示局部识别点。
8. 不改变输入角色的年龄、身份、性别表达、发型、固定外观或用户硬约束。
9. 每条负向 Prompt 覆盖身份漂移、结构错误、重复人物、文字水印和低质量问题。
10. 未成年人角色保持适龄、非性化的服装、动作、表情和叙事。

发现角色一致性问题时，回到 `character_lock` 和各镜头 Prompt 修正；不要只在 `validation.md` 记录问题。

## 异常处理

- 找不到 `role.json`：停止生成，报告预期路径，不创建伪造角色。
- JSON 无法解析：停止生成并报告解析错误。
- 同时存在 `role` 和 `roles`：优先使用 `role`，并在 `inferred_items` 记录选择。
- 输入包含多个角色但未指定对象：使用第一个角色，并在 `inferred_items` 标记；不把多个角色混合成一个人。
- 场景信息不足：补全中性、服务于角色展示的场景，不改变角色设定，并标记推断项。
- 用户明确要求其他景别：仍保证五条输出，将额外景别作为某条镜头的构图描述，不减少固定五镜头。
